When validating configurations via the web API, `qbit_manage` crashes and brings down the web server/container if the connected qBittorrent version is outside the supported range. This happens because `Qbt.__init__` calls `sys.exit(1)` when the version is unsupported. The `validate_config` method in the web API only catches `Exception`, and since `sys.exit(1)` raises `SystemExit` (which inherits from `BaseException`, not `Exception`), the exception escapes and crashes the server.

Expected behavior:
1. During web API validation, an unsupported version should not crash the server. Instead, it should be caught and returned as an error in the validation response (so that `response.valid` is `False` and `response.errors` contains an error message mentioning "only compatible with").
2. To achieve this, `Qbt.__init__` should raise a custom exception (e.g., `UnsupportedVersion` inheriting from the existing `Failed` exception) instead of calling `sys.exit(1)`. The `Failed` exception is likely defined in a utilities module, so define `UnsupportedVersion` there as well.
3. Regular CLI and scheduled runs (in the `start()` function of the main `qbit_manage.py` script) should catch this `UnsupportedVersion` exception before any generic `Failed` handlers and cleanly exit with status code 1, preserving the original CLI behavior.
4. Additionally, the web API's `validate_config` method must properly honor the `skip_qb_version_check` flag from the `commands` section of the config file being validated. Previously, validation only used the flag from the server's startup arguments (ignoring the value provided in the payload's `commands.skip_qb_version_check`). Ensure `validate_config` correctly extracts this flag from the incoming config data and includes it in the arguments passed when instantiating `Config`.
